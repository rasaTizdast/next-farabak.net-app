# Production sitemap audit (pre-release snapshot)

Captured 2026-11-10T17:16:51Z before deploying `a407fd3d`. The crawl followed redirects manually (maximum eight hops) at low concurrency. Structured-data counts came from server-rendered JSON-LD; they do not establish Rich Results eligibility. Full per-URL observations are in `2026-11-10-production-sitemap-audit.csv`.

## Crawl results

- 439 sitemap URLs fetched; all returned HTML with HTTP 200, with no network errors.
- No page lacked a canonical.
- The first crawl recorded three exact canonical-string mismatches. Two are substantive: an empty blog category and an active project page. A later raw request confirmed the homepage sitemap entry and head canonical both use `https://farabak.net` without a trailing slash; the CSV homepage canonical disagrees with that direct response, so refresh that row in the post-release crawl. No homepage URL change is needed.
- One sitemap URL was `noindex`: the empty `/support/blog/installing` category. Local sitemap generation now derives category URLs from published public posts, and Proxy checks category content before the route can stream a soft 200.
- 52 pages had more than one H1. This is a diagnostic, not a blanket SEO failure. The Reolink category was one confirmed example (two H1s); the local shared listing content renderer demotes legacy content H1s to H2 while the category title remains the page H1.
- 351 product pages emitted multiple `Product` entities in the pre-release HTML. The local Similar Products JSON-LD now emits link-only list entries; the main product entity remains on the detail page.
- 435 pages emitted one `BreadcrumbList`, two emitted none, and two emitted two. Reolink and `/products/industrial-cctv-camera/black-wonder` each had one. The double-list pages were `/about-us/activity` and `/contact-us`; both duplicate sources have been removed locally. The missing-list pages were the homepage and empty blog category.
- Raw HTML anchor checks found links from the homepage to `/products`, `/products/x-ray`, and the X-ray inspection article; `/products` links to `/products/x-ray`; the article links to `/products/x-ray`.
- The CSV `inbound_links` field counts anchor occurrences across fetched sitemap HTML, not unique referring pages. Use it as a rough link-presence indicator only.

## Local release verification

The production build completed on 2026-11-10 with `NEXT_PUBLIC_BASE_URL=https://farabak.net` and the configured application data source: TypeScript passed and Next.js generated all 150 static pages. The source `.env` does not define `NEXT_PUBLIC_BASE_URL`; a first local preview without the production base produced malformed `undefined/...` canonicals and API URLs, so the final build and server preview explicitly supplied the production URL. This was a preview configuration issue; live production page-two canonicals were already correct.

The built server returned a one-hop `308` from `/products/page/1`, `/products/reolink-cctv-camera/page/1`, and `/products/blackmagic/standard-conversion/page/1` to their respective base URLs. Valid page-two URLs returned `200` with self-referencing HTTPS canonicals at global, category, and subcategory levels. Page zero and out-of-range subcategory pagination returned real `404`s. On page two, both mobile and desktop “Previous” links pointed directly to the base listing; the Reolink category response had exactly one Persian H1. Forwarded HTTPS `www` input redirected in one hop to HTTPS apex while preserving path and query. `/opengraph-image.webp` returned `200` as `image/webp`; the CTX 5800 product emitted the verified S3 image URL in both Open Graph and Twitter metadata.

# Farabak.net: Top 10 search visibility issues

**Checked:** 19 November 2026  
**Scope:** `https://farabak.net/`, Persian organic search in Iran, primarily X-ray and Reolink pages  
**Evidence:** OpenSEO site crawl (50-page limit), connected Google Search Console property `https://farabak.net/`, live HTTP checks, five Farabak SEO role workflows, and public competitor pages.

## Executive finding

The current `.net` release is reachable and its sampled commercial pages return server-rendered HTML, HTTP 200, self-canonicals, and `index, follow`. Google confirms the main X-ray and Reolink categories are indexed. The main visibility problem is that X-ray pages rank very low after indexing, while some newer or migrated product URLs still have stale or unknown Google index records. This points more toward query targeting, content differentiation, and crawl/index processing than a sitewide Next.js rendering failure.

For Iran Web search, the latest complete 28-day Search Console period available was **20 October–16 November 2026**. It recorded **118 clicks, 1,443 impressions, 8.18% CTR, and average position 14.8**, compared with **183 clicks, 1,822 impressions, 10.04% CTR, and position 10.5** in 22 September–19 October. Position is an average across the searches that generated impressions, not a fixed rank for every query.

## Competitor comparison

The sampled competitors make the buying task explicit. [Maxa's X-ray category](https://maxasecurity.com/product-category/x-ray-devices/) lists equipment types and models and includes price guidance with a phone contact. [FIAR's X-ray category](https://fiar.co/product-category/%D8%B3%DB%8C%D8%B3%D8%AA%D9%85-%D8%A8%D8%A7%D8%B2%D8%B1%D8%B3%DB%8C-%D8%A7%D9%85%D9%86%DB%8C%D8%AA/%D8%AF%D8%B3%D8%AA%DA%AF%D8%A7%D9%87-%D8%A7%DB%8C%DA%A9%D8%B3-%D8%B1%DB%8C/) describes use cases and types, while its [40×60 model page](https://fiar.co/product/%D8%AF%D8%B3%D8%AA%DA%AF%D8%A7%D9%87-%D8%A7%DB%8C%DA%A9%D8%B3-%D8%B1%DB%8C-%DA%86%D9%85%D8%AF%D8%A7%D9%86%DB%8C-4060/) exposes detailed specifications and a quote contact. [AGSA's guide](https://agsaco.com/%D8%A8%D8%A7%D8%B2%D8%B1%D8%B3%DB%8C-%D8%A7%DB%8C%DA%A9%D8%B3-%D8%B1%DB%8C-%D8%A7%D9%85%D9%86%DB%8C%D8%AA%DB%8C/) explains what drives price and offers an enquiry form.

These are page-content observations, not proof that a particular factor caused a higher Google rank. A location-controlled Iranian Google SERP comparison was unavailable: OpenSEO's project defaults to `farabk.net`, US/English, and its provider rejected the Iran location code. Search Console itself is correctly connected to `https://farabak.net/` and filtered to Iran. The exact ZetronTech domain could not be verified, so no competitor metrics are attributed to it.

OpenSEO's site audit reached its 50-page limit and reported 440 discovered URLs not crawled in that audit. It found no critical sitewide crawl or canonical issue among those 50 pages. Backlink comparison could not be run because the OpenSEO organization had insufficient credits; therefore this report does not claim Farabak has fewer or weaker links than competitors.

## Does the `.com` site hurt `.net`?

**Not proven. Its existence alone does not automatically hurt `.net`.** A live check found `https://farabak.com/` returns HTTP 200, `index, follow`, with a self-canonical to `.com`; its `/products/x-ray` URL returned HTTP 500. This establishes a separate crawlable legacy host and a broken route, but not that Google has indexed duplicate content or that it has reduced `.net` rankings. The connected Search Console property covers `.net`, not `.com`, so `.com` index coverage and performance were not available here. Google explains that canonical signals and redirects help consolidate duplicate URLs and their signals; use a path-preserving permanent redirect to `.net` if `.com` is retired and the pages are duplicates. Otherwise, keep the sites' purposes and content distinct and monitor them as separate properties.

## Recommended order

1. Decide the intended canonical host. If `.net` is the only site, map and permanently redirect old `.com` URLs to matching `.net` pages; resolve the old 500 route.
2. In Search Console, refresh the sitemap indexing breakdown and recrawl the old/new B400 pair plus the fixed page-zero URL. Verify Google's selected canonical after it fetches the live responses.
3. Improve the indexed X-ray and luggage pages around commercial buying intent, with buyer comparisons and quote guidance before the product grid. Assign one URL to each query intent.
4. Test the Reolink title/snippet and product rich-result eligibility with truthful, maintainable product data.
5. Recheck Iran Web Search Console queries and pages in comparable complete 28-day windows. Use Google-selected canonical, impressions, clicks, CTR, and position as acceptance measures.

These changes can fix discoverability and presentation problems and improve the chance that relevant pages rank. They cannot guarantee rankings: Google still chooses what to index and rank, and the strongest ranking work will be the content, proof, and authority improvements validated against real query data. Google's guidance emphasizes accessible, useful pages and original content, rather than any single framework or metadata trick ([technical requirements](https://developers.google.com/search/docs/essentials/technical), [helpful content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content), [canonical consolidation](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)).
